AOHI charger — BLE endpoint provisioning

Points an AOHI charger at the AOHI Local Server add-on instead of AOHI's cloud, for use with the ha-aohi-charger integration. Protocol reverse engineering by atc1441.

⚠️ Read before using.
  • This rewrites persistent configuration on your charger, and afterwards the official AOHI app will no longer see it.
  • Going back means a factory reset and re-adding it in the app, which rewrites the endpoints for you. There is no undo button here: the factory values cannot be read back from the device, so anything this tool wrote as a "restore" would be a guess.
  • New endpoints only take effect after the charger is power-cycled.
  • Nothing here is needed for normal use — the cloud integration works without it.

1Connect

Factory reset the charger first — hold its button until it resets. A short press also makes it appear here and answer normally, but anything you write in that state is acknowledged and then silently discarded: only a factory-reset charger stores new endpoints.

It advertises as AOC-C022-<xx> (older units may use 7231N); tick the box above if it doesn't appear.

2Read current configuration

Safe, read-only. Required before any write is unlocked.

3Change endpoint

Finish the address, e.g. 192.168.1.42. The add-on prints its own address in its log when it starts. Uses the default ports (8099 / 8098) — switch to advanced mode to change them.
—
host2 must use wss://. Given a plain ws:// address the firmware silently never connects — no error, no connection attempt — so this tool refuses to write one. The self-signed certificate the add-on generates is fine; the charger does not verify it.

Each URL is stored in a 39-byte field and must be ≤38 characters (one byte is the terminator). The whole 126-byte frame must fit in a single BLE write; a real AOC-C022 negotiates an MTU of 517 so this is not a practical concern, but the tool refuses to fragment — a partial write would store a corrupt URL.

4Use it in Home Assistant

Once written, the charger talks only to your own server. Nothing here needs Bluetooth, so you can do it from any machine.
  1. Power-cycle the charger. The endpoints written above do not take effect until it reboots — unplug it, wait a few seconds, plug it back in.
  2. Check the AOHI Local Server add-on log. Within a minute or two it should print issued broker credentials to <serial>. If it never does, the charger has not reached the add-on: confirm the address you wrote, and that the charger joined WiFi.
  3. In Home Assistant, go to Settings → Devices & services → Add integration and choose AOHI Smart Charger. If you have not installed it yet, it is available through HACS from ha-aohi-charger.
  4. Pick Local server when asked. The address field is already filled in with the machine Home Assistant is running on, which is the right answer when the add-on is installed there. Leave the ports at 8099 and 8098 unless you changed them.
  5. Your charger appears with a switch per port, plus power, temperature and charging-mode entities.
"Connected, but no chargers have registered with that server yet" means the add-on is running fine but no charger has ever reached it. That is step 1 or 2 above, not a problem with the integration — most often the charger simply has not been power-cycled yet.
